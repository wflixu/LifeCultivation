> 原名延续，但完全重构。从「习惯追踪」改版为「AI 减肥记录工具」。
> 目标用户：自己。先满足自己的需求，后续再考虑上架。

---

## 1. 产品定位

一款**以热量平衡为核心**的 iOS 个人减重辅助工具。

### 核心公式

人体每日总消耗（TDEE）由三部分组成：

```
TDEE = 静息消耗 + 日常活动消耗 + 运动消耗
     ├── 静息消耗 (Resting Energy, ≈60-70%)
     │   维持生命基本运转（呼吸、心跳、体温），相当于基础代谢率 BMR
     │   有 Apple Watch → 从 HealthKit 读取（基于心率+个人数据实时计算）
     │   无 Watch → Mifflin-St Jeor 公式估算
     │
     ├── 日常活动消耗 (NEAT, ≈15-30%)
     │   走路、站立、做家务等非刻意运动的日常活动
     │   有 Watch → 包含在 Active Energy 里
     │
     └── 运动消耗 (EAT, ≈5-10%)
         刻意运动（跑步/游泳/力量训练）
         有 Watch → 从 HealthKit 读取 workouts
```

**减重的本质是热量缺口：**

```
每日净热量 = 摄入量 - TDEE
           = 摄入量 - (静息消耗 + 活动消耗 + 运动消耗)

净热量 < 0 → 热量缺口 → 减重
净热量 > 0 → 热量盈余 → 增重
```

**关键决策线：静息消耗（Resting Energy）**

这是你今天什么都不做也会烧掉的热量。它决定了：
- **摄入 < 静息消耗** → 躺着不动也会瘦（但长期不建议）
- **静息消耗 < 摄入 < TDEE** → 合理的减脂区间，配合运动效果更好
- **摄入 > TDEE** → 会增重

> 你之前用的 App 里的「基础代谢线」就是这个概念。但这个 App 更进一步——有 Apple Watch 实时数据会更准。

### 与竞品的差异

- 中文食物友好 — 胡辣汤、煎饼果子、杂粮煎饼等都能识别
- AI 驱动记录 — 拍照或文字描述即可记录，不用翻数据库
- 收藏机制 — 常吃的食物识别一次，之后一键添加
- 精确的热量模型 — 静息消耗 + 活动消耗 两层，Apple Watch 加持

## 2. 核心功能

### 2.1 饮食记录（核心）

#### 记录方式（分阶段上线）

**Phase 1（MVP）：文字描述 + 预制收藏**
- 输入文字描述，如「两个包子一碗胡辣汤」
- AI 根据描述估算热量和营养，返回结构化 JSON
- 支持中文常见食物，AI 按常识份量估算（中杯可乐 ≈ 400ml ≈ 170kcal）
- 预制一些常见食物快捷入口（包子、油条、胡辣汤、杂粮煎饼等）

**Phase 2（后续）：图片识别**
- 拍照或从相册选图
- 多模态大模型识别食物 → 返回营养数据
- 放到后面做，因为：① 图片识别成本高 ② 文字描述反而更准 ③ 技术上更复杂

#### 收藏机制（关键体验）

- 每次 AI 识别结果可以收藏，存入「常用食物」
- 收藏项可编辑份量和热量
- 按使用频率排序，常吃的排前面
- 下次直接点击添加，不用再调 AI

#### 用餐时段

每天分 3 个时段，记录时选择所属时段：

```
早餐       (05:00-10:00)
午餐       (11:00-14:00)
晚餐       (17:00-21:00)
```

时段用颜色标签区分，方便快速浏览三餐分布。记录时选时段不是强制的，也可以不选直接平铺。

#### 展示方式

每日饮食通过营养卡片分餐展示，不另设平铺列表。

#### 跨日记录

- 默认记录当天
- 支持「记昨天的」— 日期选择器可切换到前一天

### 2.2 运动记录

- 读取 Apple Health / Apple Watch 运动数据
- 自动同步运动消耗热量
- 手动补充（可选）：没戴手表时的运动可手动添加

### 2.3 个人信息（HealthKit 读取）

App 首次启动时请求 HealthKit 权限，读取以下数据：

| 数据 | 来源 | 说明 |
|------|------|------|
| 体重 | HealthKit（可来自智能秤/手动输入） | 每日自动读取最新值 |
| 身高 | HealthKit | 首次读取后缓存，有变更时更新 |
| 年龄 | HealthKit（出生日期） | 首次读取后缓存 |
| 静息消耗 | HealthKit（Resting Energy） | 有 Apple Watch 时自动获取 |
| 活动消耗 | HealthKit（Active Energy） | 有 Apple Watch 时自动获取 |
| 运动记录 | HealthKit（Workouts） | 同步跑步/游泳/力量训练等 |

无 Apple Watch 时的降级方案：
- 静息消耗 → Mifflin-St Jeor 公式（用身高/体重/年龄算 BMR）
- 活动消耗 → BMR × 活动系数，用户在设置中自选（久坐/轻度/中度/活跃）

### 2.4 核心计算与展示

#### 热量模型

```
静息消耗 (Resting Energy)
  ├── 有 Apple Watch → HealthKit 读取（实时心率校准）
  └── 无 Watch → Mifflin-St Jeor 公式计算
       男性 BMR = 10 × 体重(kg) + 6.25 × 身高(cm) - 5 × 年龄 + 5

活动消耗 (Active Energy)
  ├── 有 Apple Watch → HealthKit 读取（日常活动 + 运动合计）
  └── 无 Watch → 静息消耗 × 活动系数（久坐 1.2 / 轻度 1.375 / 中度 1.55）

每日净热量 = 食物摄入 - (静息消耗 + 活动消耗)

热量状态：
  │ 赤字 (Deficit)    → 净热量 < 0     → 体重下降
  │ 盈余 (Surplus)    → 净热量 > 0     → 体重上升
  │ 维持 (Maintain)   → 净热量 ≈ 0     → 体重不变

剩余热量 = 平衡热量(TDEE) - 已摄入 + 运动消耗
          // 还能吃多少不超预算

累计效应：
  7,700 kcal 缺口 ≈ 1 kg 脂肪
```

#### 首页 Dashboard

```
┌──────────────────────────────────┐
│  📅 6月7日                        │
│                                  │
│  ┌──────────────────────────┐    │
│  │   热量总览                 │    │
│  │                          │    │
│  │  平衡热量（TDEE）  2,070 │ ← 你的每日预算    │
│  │  已摄入            1,200 │ ← 饮食合计        │
│  │  已消耗              350 │ ← 运动            │
│  │  剩余              1,220 │ ← 还能吃这么多     │
│  │                          │               │
│  │  圆环：[■■■■■□□□□□]      │ ← 已摄入/平衡热量  │

└──────────────────────────────────┘
```

**关键交互：**
- 圆环图直观反映「今天还剩多少预算」
- 剩余为正 → 绿色（预算内），剩余为负 → 红色（超标）

#### 历史趋势

- 净热量趋势图（日/周/月）
- 累计热量缺口图（显示已减的理论脂肪量）

#### 连续记录（Streak）

不设提醒/通知，用 Streak 机制激励持续记录：

| Streak 类型 | 说明 |
|------------|------|
| 记录连续天数 | 连续每天至少记录一次饮食 |
| 达标连续天数 | 连续每天净热量 ≤ 目标 |

显示位置：个人资料 Tab → 概况卡片

## 3. 数据模型

```
DailyRecord
├── date: Date
├── foods: [FoodEntry]          // 饮食记录列表
├── weight: Double?             // 当日体重
│
├── restingEnergy: Double       // 静息消耗 (kcal)
│   // 有 Watch → HealthKit RestingEnergy
│   // 无 Watch → Mifflin-St Jeor 公式计算
├── activeEnergy: Double        // 活动消耗 (kcal)
│   // 有 Watch → HealthKit ActiveEnergy
│   // 无 Watch → 估算值
├── tdee: Double                // 总消耗 = resting + active
├── totalIntake: Double         // 总摄入 = 所有 food.calories 之和
├── netCalories: Double         // 净热量 = totalIntake - tdee
├── deficit: Double             // 累计热量缺口（用于预测减重）
├── waterCups: Int              // 今日饮水杯数（每杯 250ml）
│
├── height: Double              // 身高(cm)，用于计算 BMR
├── age: Int                    // 年龄
└── activityLevel: Double       // 活动系数（无 Watch 时估算用）

FoodEntry
├── id: UUID
├── name: String                // 食物名称
├── calories: Double            // 热量
├── protein: Double?            // 蛋白质
├── fat: Double?                // 脂肪
├── carbs: Double?              // 碳水
├── serving: String             // 份量描述（"一碗"、"200ml"）
├── source: enum                // photo / text / favorite
├── timestamp: Date
└── imageData: Data?            // 拍照时保存原图

FavoriteFood
├── id: UUID
├── name: String
├── calories: Double
├── protein: Double?
├── fat: Double?
├── carbs: Double?
├── serving: String
├── imageData: Data?
├── useCount: Int               // 使用次数（排序用）
└── lastUsed: Date

ExerciseEntry
├── id: UUID
├── type: String                // "跑步"、"游泳"、"力量训练"
├── duration: TimeInterval      // 分钟
├── calories: Double
├── source: enum                // healthKit / manual
└── timestamp: Date
```

## 4. 技术方案

| 模块 | 方案 |
|------|------|
| 语言 | Swift 6 |
| UI 框架 | SwiftUI |
| 数据持久化 | SwiftData |
| AI 图片识别 | 多模态大模型 API（GPT-4o / Gemini 等），拍食物图 → 返回结构化 JSON |
| AI 文字估算 | 同一模型，传入文字描述 → 返回结构化 JSON |
| 运动数据 | HealthKit（读取 workouts） |
| 体重数据 | HealthKit（读取/写入体重） |
| 图表 | Swift Charts |
| 最低版本 | iOS 18+（SwiftData + Swift Charts 支持） |
| 架构 | MVVM |

**AI Prompt 设计参考：**

图片识别 prompt：
```
你是一个营养师。分析这张图片中的食物，返回 JSON 格式：
{
  "foods": [
    {"name": "胡辣汤", "serving": "一碗", "calories": 120, "protein": 5, "fat": 3, "carbs": 18},
    {"name": "包子", "serving": "2个", "calories": 280, "protein": 10, "fat": 8, "carbs": 42}
  ]
}
尽量准确估算中餐常见食物的热量，以中国常见份量为基准。
```

文字描述 prompt：
```
用户描述了他吃的食物，请估算热量和营养，返回 JSON 格式（同上）。
例如：「喝了一杯中杯可乐，吃了两个包子和一碗胡辣汤」
注意：中杯可乐约 400ml ≈ 170kcal，不需要用户说毫升数，
你根据常识估算常见份量。
```


选中类型后进入详情填写：
- **有距离的运动**（跑步/骑行/步行）：填写距离(km) → 自动估算热量
- **按时间计的运动**（力量/瑜伽/其他）：填写时长(分钟) → 自动估算热量

**热量估算公式（简化版）：**

按 MET（代谢当量）估算：
```
热量(kcal) = MET × 体重(kg) × 时长(小时)

跑步 8km/h → MET ≈ 8
步行 5km/h → MET ≈ 3.5
骑行 15km/h → MET ≈ 6
力量训练 → MET ≈ 5
瑜伽 → MET ≈ 3
游泳 → MET ≈ 7
```

- 距离型运动：先根据配速估算时长，再算热量
- 基础 MET 值可在个人资料查看/调整
